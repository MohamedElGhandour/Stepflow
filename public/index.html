Worth knowing

Four things the API guarantees

Each of these is a behaviour you can rely on, not a setting to find. They are covered by tests in the repository.

Your targets stay clickable

The overlay is pointer-events: none, so a step can point at a button and the user can still press it. closeOnClick is off by default.

Throwing aborts the move

Reject from onNext and the tour stays on that step so the user can fix the problem and try again. Reporting an error never ends the tour.

Nothing to clean up

Listeners, the scroll lock and the portal are tied to the component's lifetime. Unmount mid-tour and everything releases.

Keys stay yours

Arrow keys and Escape are ignored while focus is in an input, textarea, select or contenteditable — so a step can point at a form.
